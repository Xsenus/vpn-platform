# Agent Instructions

Эти правила обязательны для каждого агентского прохода в этом репозитории.

## Roadmap And Progress Reporting

- Если задача связана с roadmap, статусом проекта, приемкой или закрытием пунктов, в итоговом ответе обязательно указывать:
  - сколько задач выполнено;
  - сколько задач осталось;
  - процент готовности;
  - сколько пунктов открыто, в работе и заблокировано, если эти статусы есть в источнике.
- Процент готовности считать от общего количества проверяемых пунктов: `выполнено / всего * 100`.
- Если данные берутся из roadmap или другого markdown-документа, указывать источник и дату/версию статуса, если они есть.

## Artifact Cleanup

- После выполнения задачи обязательно убрать за собой временные артефакты: временные файлы, локальные отчеты, screenshots, test output, generated smoke reports, debug logs и другие файлы, созданные только для проверки.
- Если артефакт нужен как доказательство для roadmap, приемки или расследования, его можно оставить только при явной пользе; в итоговом ответе нужно перечислить путь к артефакту и подтвердить, что в нем нет секретов.
- Нельзя оставлять cookies, tokens, bearer headers, private keys, `.env`-файлы, connection strings, пароли или raw provider payloads в артефактах.

## Testing Requirements

- Если пользователь явно не написал, что тесты запускать не нужно, каждая добавленная или измененная функция должна быть покрыта релевантным тестом.
- Для изменений в коде запускать минимально достаточный набор тестов, который подтверждает затронутое поведение. Для общих или рискованных изменений запускать более широкий suite.
- Если в проекте есть локальная БД или локальный SQLite-режим, новые пользовательские, API, payment, VPN, admin, cabinet и provisioning-сценарии нужно проверять на локальной БД.
- Если тест, локальная БД или внешняя проверка недоступны, в итоговом ответе нужно явно указать, что не было проверено, почему и какой остаточный риск остается.

# Управление платежными провайдерами

Раздел админки `Оплаты` позволяет подключать и редактировать платежные аккаунты без изменения кода. Настройки хранятся в таблице `PaymentProviderAccounts`, секреты защищаются через `ISecretProtector` и не возвращаются в API.

## Что поддерживается

- YooKassa
- RoboKassa
- YooMoney
- Telegram Stars
- CloudPayments
- TBank Acquiring
- Prodamus
- Stripe
- PayPal

## Поля настройки

- `Платежная система` - провайдер, который будет использоваться при создании платежа.
- `Режим` - `Disabled`, `Sandbox` или `Production`.
- `Внутреннее имя` - техническое имя аккаунта для админки и логов.
- `Название для пользователя` - название, которое пользователь видит при выборе оплаты.
- `ShopId / MerchantLogin` - идентификатор магазина, терминала или merchant account.
- `API base URL` - базовый адрес API провайдера. Если оставить пустым при создании, backend подставит безопасное значение по умолчанию для известных провайдеров.
- `Секретный ключ` - основной секрет провайдера. После сохранения не показывается.
- `Секрет webhook` - секрет для проверки уведомлений. После сохранения не показывается.
- `Адрес возврата после оплаты` - куда пользователь возвращается после оплаты.
- `Webhook URL` - адрес webhook на стороне платформы, который нужно указать в кабинете платежного провайдера.
- `Allowed IP ranges` - список CIDR/IP для проверки webhook, если включено ограничение по IP.
- `Extra settings JSON` - дополнительные параметры провайдера, например `hostedCheckoutUrl` для CloudPayments.

## Безопасное редактирование

При редактировании существующего платежного аккаунта пустые поля `Секретный ключ`, `Секрет webhook` и `Extra settings JSON` не затирают текущие значения. Чтобы заменить секрет или JSON-настройки, нужно ввести новое значение явно.

`Extra settings JSON` должен быть валидным JSON-объектом. Строки, массивы и невалидный JSON отклоняются backend-валидацией.

## Проверка готовности

Админка показывает готовность каждого аккаунта:

- включен ли аккаунт;
- не находится ли он в режиме `Disabled`;
- заполнен ли `ShopId / MerchantLogin`;
- есть ли секрет для production-режима;
- корректно ли заполнены API base URL, Return URL и Webhook URL;
- какие возможности заявлены адаптером провайдера: создание платежа, webhook, возврат, повторная проверка, sandbox/live.

Провайдер появляется пользователям только после настройки и включения. Реальные live-платежи нужно включать только после добавления production-ключей и проверки webhook на стороне провайдера.

Кнопка `Проверить` в админке запускает backend-проверку аккаунта без создания реального платежа и без списаний. Проверка обновляет `HealthStatus`, время последней проверки и показывает список найденных проблем.

# Раздел «Что нового»

Модуль «Что нового» показывает пользователю опубликованные изменения платформы и дает администратору управлять релизами из админки.

## Что реализовано

- В backend добавлены сущности `AppRelease`, `AppReleaseItem`, `AppReleaseSeen`.
- Добавлены таблицы `AppReleases`, `AppReleaseItems`, `AppReleaseSeen` и EF Core migration.
- Backend при старте синхронизирует агентские релизы из `backend/src/VpnPlatform.Api/AppReleases/releases.json`.
- Релизы с `Source = manual`, созданные в админке, не перезаписываются JSON-файлом.
- Пользовательский кабинет запрашивает последний активный опубликованный релиз.
- Если пользователь еще не видел релиз, окно «Что нового» открывается автоматически.
- После закрытия релиз помечается просмотренным на сервере и дополнительно запоминается в `localStorage`.
- Пользователь может открыть окно вручную кнопкой «Что нового» в навигации кабинета.
- Внутри окна доступна история релизов и кнопка возврата к текущему релизу.
- В админке добавлен отдельный раздел «Что нового» для просмотра, создания, редактирования и удаления релизов.

## API

Пользовательские endpoints требуют авторизацию:

- `GET /api/app-version/latest` - возвращает последний активный опубликованный релиз и признак просмотра текущим пользователем.
- `GET /api/app-version/history` - возвращает историю активных опубликованных релизов.
- `POST /api/app-version/mark-seen` - помечает релиз просмотренным текущим пользователем.

Админские endpoints требуют admin-права:

- `GET /api/app-version/admin/releases` - список релизов для админки.
- `POST /api/app-version/admin/releases` - создание релиза.
- `PUT /api/app-version/admin/releases/{id}` - обновление релиза.
- `DELETE /api/app-version/admin/releases/{id}` - удаление релиза.

## Seed-релизы

Агентские релизы лежат в файле:

```text
backend/src/VpnPlatform.Api/AppReleases/releases.json
```

Формат одного релиза:

```json
{
  "releaseId": "2026-05-27-whats-new-module",
  "version": "0.2.0",
  "releasedAt": "2026-05-27T00:00:00Z",
  "title": "Раздел «Что нового» для обновлений платформы",
  "summary": "Кабинет и админка получили единый механизм показа обновлений.",
  "isActive": true,
  "source": "agent",
  "items": [
    {
      "type": "new",
      "text": "В кабинете появилась кнопка «Что нового» и автоматическое окно последнего релиза.",
      "sortOrder": 10
    }
  ]
}
```

Типы пунктов: `new`, `improved`, `fixed`, `important`.

## Проверка локально

1. Запустить API в режиме `Local`.
2. Войти под локальным администратором `admin@local.test`.
3. Проверить `GET /api/app-version/latest`: должен вернуться релиз `2026-05-27-whats-new-module`.
4. Вызвать `POST /api/app-version/mark-seen` с этим `releaseId`.
5. Повторно вызвать `GET /api/app-version/latest`: поле `seenByCurrentUser` должно стать `true`.
6. Открыть админку и проверить отдельный раздел «Что нового».

## Покрытие тестами

- Backend-тесты проверяют latest/history, отметку просмотра, появление нового релиза, игнорирование будущих и неактивных релизов, admin CRUD и seed из JSON.
- Frontend-тесты проверяют методы API-клиента и наличие gate/modal в кабинете и редактора релизов в админке.

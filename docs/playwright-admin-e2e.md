# Playwright E2E: админка

Этот набор закрывает roadmap-пункт `P9-TST-005` и проверяет основной путь администратора без живого backend, реальных платежей, Telegram, VPS и 3x-ui:

- вход администратора;
- дашборд и блок готовности к live-продажам;
- раздел оплат и проверка платежного провайдера;
- создание тарифа;
- просмотр VPN-доступа;
- раздел 3x-ui панелей, проверка подключения, синхронизация, inbound-ы и клиенты;
- создание сценария работы;
- создание релиза для раздела «Что нового»;
- отсутствие 404 и ошибок в консоли браузера.

## Запуск

```powershell
cd frontend
npm run e2e:admin
```

Playwright поднимает три Vite-приложения через `frontend/scripts/playwright-webservers.mjs`:

- public web: `http://127.0.0.1:5293`;
- cabinet: `http://127.0.0.1:5294`;
- admin-panel: `http://127.0.0.1:5295`.

API-запросы `/api/**` мокируются внутри теста. Сценарий безопасен для локальной машины и CI: он не ходит в настоящие платежные системы, Telegram, VPS, 3x-ui и не требует живой БД.

## Первый запуск на новой машине

Если браузер Playwright ещё не установлен:

```powershell
cd frontend
npx playwright install chromium
```

## Что считается зелёным

- `npm run e2e:admin` проходит в проекте `admin-panel`;
- login открывает админские вкладки;
- разделы `Оплаты`, `Тарифы`, `VPN-доступы`, `3x-ui панели`, `Сценарии`, `Что нового` открываются как отдельные tabpanel;
- платежный провайдер проходит проверку подключения;
- тариф, сценарий и релиз создаются через формы;
- panel test и panel sync возвращают успешные статусы;
- нет HTTP-ответов 400+ и console/page errors;
- `.github/workflows/ci.yml` и `.github/workflows/staging-validation.yml` запускают `npm run e2e:admin`;
- release seed содержит `2026-06-13-playwright-admin-e2e`.
